CONNECT YOUR TOOLS

One backend. Three ways in.

One stable configuration follows your primary cluster on every device. Book a cluster first, then choose how to connect.

01 / FULL CONTROL

Developer CLI

Book, select, share, and stop environments. Administrator commands are available to approved admins.

devctl login
devctl start
export KUBECONFIG="$(devctl setup)"
kubectl get pods
devctl sessions
Client installation required
02 / EVERYDAY KUBECTL

kubectl plugin

Log in and refresh tokens automatically. Book clusters in the UI or full CLI; switch an existing booking with the plugin.

export KUBECONFIG="$(kubectl devctl login)"
kubectl devctl switch CLUSTER_ID
kubectl get pods
Plugin installation required
03 / NO EXTRA INSTALLATION

Browser kubeconfig

Download one personal config. Stock kubectl follows your current primary cluster without installing a helper.

export KUBECONFIG=/path/to/download.yaml
kubectl get namespaces
Only kubectl required

Your reusable browser kubeconfig

This file contains a personal gateway token and works across your primary-cluster changes. You can create it before booking. Original cluster credentials stay on the backend.

PATs expire and do not refresh themselves; create a replacement after expiry or revocation. Stopping a booking does not revoke this token. Signing out releases your bookings but does not revoke your PATs.

ADMINISTRATION

Manage the workspace

Administrative changes are audited. No action here deletes Kubernetes workloads.

Booking policy

Each developer can hold one cluster by default. Increase the default or set a developer-specific override. Lowering a limit preserves existing bookings and prevents new ones until the developer is below the limit.

Limits apply across all browsers, terminals, profiles, and shared bookings for the same SSO identity. Kubernetes requests, open authenticated connections, primary selection, and interaction with a visible browser page extend only the selected booking. An idle tab or token refresh does not. Shortening inactivity time can release already-idle bookings.

Developer overrides

Leave the override empty to inherit the default

Register a cluster

Import an approved, trusted kubeconfig. The server encrypts it before storage. Registration does not connect to or modify the cluster.

Cluster placement controls

Deregister an unused cluster to remove its stored credentials from devctl. Release all active bookings first. Booking history and Kubernetes workloads remain.

Release a booking

End a booking. If it is primary, the oldest remaining booking becomes primary; otherwise kubectl reports no cluster is booked. Personal gateway tokens remain valid until their own expiry or revocation. Workloads remain.
