# ADR 013: small audit-backed lifecycle webhooks

Status: accepted. Implements the user's request for simple maintenance and use, reducing the earlier architecture proposal.

## Decision

Use the existing audit transaction as the event source and add only `webhooks` and `webhook_deliveries`. One serial worker per backend sends fixed signed HTTPS JSON; database leases coordinate replicas. Rules select an explicit business-event catalogue and optional cluster/equality-label filters. Snapshot receiver, key, event and deadline on enqueue. No target/event/version service, workflow DSL, arbitrary expressions or provider adapter is introduced.

Notifications complete on HTTP acceptance. Only `cluster_idle` can create a blocking hold, atomically with the last participant's release or expiry. Success is an operation-scoped callback followed by two fresh health passes. Failed/timed-out work remains held; manual maintenance and other holds stay independent. Serial blocking execution permits reuse of existing health recovery instead of a second health scheduler or per-workflow probe engine.

Protect destinations with an operator origin allowlist, verified TLS, validated DNS dialing and no redirects/unsupported proxies. Store signing secrets encrypted; show them once and derive callback capabilities for immutable delivery IDs/deadlines. Receivers must deduplicate the stable idempotency key. Administrative retry keeps the same delivery; state-checked resolution requires review and confirmation external work stopped.

## Consequences

The same mechanism handles most business audit actions without a generic workflow engine. Fewer tables and a fixed protocol keep the MVP understandable. HTTP delivery remains at least once; there is no exactly-once pipeline guarantee. Existing requests/workloads can outlive released gateway access, so pipeline preflight/drain and destructive permissions belong to the integration. Native CI adapters, automated cancellation, distributed draining and upstream credential replacement remain outside this implementation.
