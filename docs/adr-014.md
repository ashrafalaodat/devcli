# ADR014: versioned administrator cluster and kubeconfig editor

Status: accepted. Extends ADR011's label editor and the encrypted registry; administrators may explicitly view and replace original credentials.

## Decision

Let SSO administrators edit display name, placement labels, maintenance, maximum shared holders, fixed health profile and kubeconfig text in one Slate dialog. Keep cluster ID, history and runtime reservations immutable through this editor. Do not introduce a separate configuration service or change Kubernetes privileges.

Add one `registry_version` column in migration12. A trigger increments it only when editable configuration changes. Full saves require the loaded `expected_version`, checked under the existing PostgreSQL reservation lock; stale requests fail atomically with409. Keep maintenance-only and labels-snapshot clients compatible. Reject duplicate live display names and a holder limit below the current booked count.

Keep original kubeconfigs out of ordinary cluster/session responses. Provide an administrator-only `POST /v1/admin/clusters/{id}/kubeconfig` with a required audit reason, browser Origin/CSRF checks and `Cache-Control: no-store`. Audit the view without its contents. The GUI reveals text only after an explicit request, stores it in an uncontrolled textarea, and clears it on hide, reload, close or unmount. Do not create a download or browser-storage record.

Only changed credentials are submitted. Validate the same single-context, embedded static credential and verified-TLS rules as registration; encrypt before persistence. Audit changed field names, never credential values. Emit safe `cluster_update` notification metadata; exclude secret viewing from webhook subscriptions. A profile or credential change fences health results/probes and queues new checks. Existing streams pin and recheck configuration generation so they stop using a replaced connection without ending bookings or changing authentication.

## Consequences

Administrators can copy the credentials they are allowed to view. Avoiding a download reduces accidental persistence but cannot erase browser/OS memory or protect against an administrator's deliberate actions. Developers continue to receive only gateway configurations. Normal metadata, audit logs and webhook bodies contain no original credential values.

Changing configuration does not revoke old upstream credentials or roll back operations already accepted by Kubernetes. Existing bookings and PATs remain, while new allocation waits for two passing health checks. Do not repoint an occupied registration to a different physical environment. ID changes still require deregistration and a new registration, preserving history.

Tests use isolated PostgreSQL schemas, disposable verified-TLS API fixtures, local Keycloak and the production React UI. Corporate identity and real Kubernetes mutation are outside these changes.
