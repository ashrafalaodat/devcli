# ADR012: automatic Kubernetes API health monitoring

Status: accepted, revised to make monitoring mandatory by user request. Supersedes the original Disabled/Observe/Enforce rollout modes.

## Decision

Run a bounded worker in `devctld` for every live registered cluster using the existing encrypted static kubeconfig and verified client-go transport. The default `api-ready.v1` checks version, discovery and readiness; an explicit `discovery-only.v1` exception omits readiness. Fixed GET paths preserve endpoint prefixes and refuse redirects. Checks create no Kubernetes resources and never call developer gateway, activity or reservation operations.

Migration11 removes the old global rollout mode. Fresh passing observations always gate new manual/shared reservations and PAT fallback. Existing reservations and primary/access remain independent. A failing check never evicts a holder or switches their cluster.

Use short PostgreSQL claims and per-cluster leases, then do network work outside transactions. Publication checks the token, sequence, deadline, configuration generation and policy revision under the reservation lock. Derive staleness from database UTC time. First failure closes new placement; two consecutive successful cycles recover it, and stale gaps reset recovery.

Expose safe summaries and audited check/profile operations, with no monitoring-mode setting in the API, CLI or GUI. Configuration edits and lifecycle verification barriers invalidate old observations and in-flight claims. Keep backend readiness independent of remote outages.

## Consequences

Registration immediately schedules automatic read-only requests; register only approved targets. New clusters wait for passing checks before bookings. Existing databases receive this behavior without losing reservations or credentials. Operational network/CA access must be consistent across backend replicas.

Passing discovery does not establish authenticated identity, application permissions, capacity or workload readiness. A403 readiness error needs an explicit permission/profile decision rather than silent weakening. Active identity reviews, history services and arbitrary probe definitions remain deferred.
