# ADR 012: durable, opt-in Kubernetes API health monitoring

Status: accepted. Extends the reservation gateway with read-only health observations and optional placement enforcement.

## Decision

Run a bounded worker in `devctld` using existing encrypted static kubeconfigs and verified client-go transports. The default `api-ready.v1` profile checks version, discovery and readiness; an explicit `discovery-only.v1` exception omits readiness. Probes use fixed GET paths, preserve endpoint prefixes and never follow redirects, create Kubernetes resources, invoke developer credentials or call activity/reservation code.

Persist global rollout mode in PostgreSQL. Migration 9 defaults to Disabled and preserves existing data. Observe performs checks without a health booking gate; Enforce requires fresh passing observations for new manual/shared reservations and PAT automatic fallback. Existing primary/access and inactivity rules remain independent. Failed checks do not evict holders or switch their primary.

Use short `SKIP LOCKED` claim transactions and per-cluster leases, then perform network work outside transactions. Publish under the reservation lock with lease token/sequence, expiry, configuration generation and policy revision checks. Configuration/profile changes and deregistration invalidate old results; mode changes fence old claims. Derive staleness from database UTC time and reset recovery after stale gaps. The first failure closes new placement in Enforce mode; two successful cycles recover it. Four probes may run concurrently per backend instance.

Expose safe health summaries to approved users and audited mode, profile and refresh operations to administrators. Keep health separate from reservation/maintenance labels in the Slate GUI. Coalesce refreshes, protect profile edits against stale revisions, and keep fixed diagnostic categories free of response bodies, URLs and credentials. CLI waiting reports a completed cycle rather than pretending one success always establishes recovery.

## Consequences

Registration capacity no longer needs to be confused with current API reachability when enforcement is enabled. Monitoring failure cannot revoke an existing booking, and a passing observation still cannot guarantee a later request. Readiness permissions must be reviewed rather than silently downgraded. Public GET success does not verify authenticated identity, workload permissions, capacity or application health.

Replicas initially require equivalent egress, proxy and CA access. Active identity reviews, resource-producing checks, lifecycle callback barriers, external metrics/history services and arbitrary probe definitions are not part of this release. The [health architecture](cluster-health-architecture.md), [security notes](security.md), [OpenAPI](openapi.json) and [verification record](verification.md) describe operational details and test limits.
