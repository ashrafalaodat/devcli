# ADR 010: approved Slate workspace and focused administration

Status: accepted. The user approved Concept A, **Slate**, on 12 November 2026. Extends ADR009's React implementation while preserving the product and authentication decisions in ADRs005–008.

## Context

The browser needs a clearer daily workflow as cluster bookings, primary selection, token preferences and administration grow. The previous interface exposed many forms together and placed all administrator operations on one long page. Two visual concepts were reviewed before implementation; the approved direction uses a light canvas, navy sidebar and blue primary actions.

## Decision

Implement Slate directly in the existing React and TypeScript application. Keep the current backend API, OIDC flow, database schema, Vite build and embedded Go deployment. Add no UI framework, runtime service or package dependency.

Make the identity's current primary cluster a persistent context and the main workspace focus. Show owned bookings, last activity, the inactivity deadline, effective booking limit and team contacts. Use focused drawers for booking and personal kubeconfig creation or policy edits. Keep automatic and explicit cluster selection distinct, with clear reasons when a booking is unavailable. Availability represents reservations, not Kubernetes health, resource capacity or scheduling readiness.

Separate administration into cluster registry, people and booking policy, organisation tokens, and audit views. Registration, placement changes, deregistration, developer overrides and administrative release use focused forms. Keep audit reasons and the affected identity or cluster beside the action. Search and filters operate on the loaded data; audit filtering is explicitly limited to the latest100 events.

Use native modal `<dialog>` elements with labelled headings, initial focus, an inert background, keyboard focus containment, safe Escape dismissal and focus return. Block dismissal and duplicate submissions while a mutation is pending. Show recoverable request errors and linked field-error summaries without discarding entered values. Replace dense mobile tables with readable records that retain their actions, and provide visible developer and administrator navigation on narrow screens. Respect reduced-motion preferences and use text alongside status colors.

Cancel pending confirmations when authentication is cleared or rejected. Resolve the waiting action as declined before removing the workspace, so a stale dialog cannot keep the sign-in page inert or later invoke its previous action. Preserve the original focus trigger before marking asynchronous controls busy.

## Product rules retained

Reservations remain whole-cluster coordination through the authenticated gateway. Exclusive use is the default; only the controlling holder enables sharing. The default developer booking limit remains1, with administrator defaults and overrides. Primary selection remains identity-wide across profiles, terminals and devices; changing it does not migrate workloads.

Activity extends only the cluster being used. Idle tabs, passive reads and authentication refresh do not extend the inactivity deadline. PAT expiry remains fixed and separate from reservation inactivity. Logout and release preserve PATs and workloads; explicitly enabled PAT automatic booking can reserve again on a later Kubernetes request. Automatic booking stays off by default, its selector remains editable, and an existing primary takes precedence.

Keep role and ownership enforcement on the backend. Preserve booking idempotency and ordered refreshes, audited changes, occupied-cluster deregistration conflicts, CSRF checks and the strict production CSP. Imported credentials and one-time PAT downloads remain transient browser values rather than React or browser storage. No new Kubernetes operation or privilege is introduced.

## Consequences and validation

The same backend capabilities now have shorter, clearer workflows and separate administrator views. Shared controls provide consistent dialogs, errors and pending states. The prototype image package remains a local review artifact and is not a production asset or build dependency; the application renders its interface from React and CSS.

Validation covers the production bundle under its real CSP, keyboard/dialog behavior, mobile actions, passive-activity guards, idempotent retries, ownership and administrator controls, credential handling, and failure recovery. Go, PostgreSQL and real local Keycloak/gateway suites separately verify the unchanged application contracts. Commands and actual results are recorded in [verification](verification.md).

These checks do not establish full WCAG conformance, screen-reader coverage, compatibility with every identity provider, or validation against real Kubernetes workloads. Corporate identity systems, production proxies and broader platform accessibility remain deployment checks. The redesign does not alter the existing coordination-only security boundary.
